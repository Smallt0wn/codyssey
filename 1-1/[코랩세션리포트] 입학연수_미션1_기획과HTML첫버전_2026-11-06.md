# 코랩 세션 리포트 - 질문하며 기획하고 HTML 첫 버전 만들기

오늘의 학습활동에서는 **‘영화 티어리스트를 만들고 싶다’는 아이디어**를 바탕으로 AI와 질문과 답변을 주고받으며 기획서를 작성했습니다. 같은 아이디어에서 출발했지만, **AI에게 어떤 질문을 했고 어떤 답변을 받았는지는 사람마다 다릅니다. 그렇다면 다른 사람은 어떤 질문을 통해 나와 다른 결과를 얻었을까요?**

다른 사람의 질문에서 내가 미처 생각하지 못한 관점을 발견할 수도 있고, 내가 받지 못했던 AI의 답변을 어떻게 이끌어냈는지 알아볼 수도 있습니다. 실제 업무에서도 동료들과 작업 과정과 결과를 공유하고 비교하며 서로의 접근 방식에서 배우는 과정이 중요합니다.

**코랩 세션**은 같은 학습활동을 마친 동료와 1:1로 각자의 작업 과정과 결과물을 공유하고 이야기하는 시간입니다. 이 리포트는 세션 전과 세션 중, 세션 후에 걸쳐 작성하며, 자신의 작업을 설명하고 이해하지 못한 부분을 동료와 함께 확인한 뒤 서로의 접근 방식과 결과를 비교합니다.

각 항목을 순서대로 작성하고, 작성하지 못한 항목이 있다면 그 이유를 기록합니다.

7장 동료평가는 2-2 진행 체크리스트의 항목을 동료가 했는지 체크하는 평가 항목입니다. 7장 이외의 항목은 세션 뒤에 작성을 마칩니다. 작성을 마친 내용은 산출물로 제출하며, 제출 방법은 운영 안내를 따릅니다.

## 1장. 개요

이번 코랩 세션에서는 각자 작성한 기획서와 HTML 결과물을 공유하고, 같은 아이디어가 서로 다른 기획과 화면으로 발전한 과정을 살펴봅니다.

AI와 함께 기획서를 작성하고 HTML을 만드는 과정에서는 AI가 제안한 내용을 받아들이기도 하고, 자신의 생각에 맞게 수정하거나 제외하기도 했을 것입니다. 하지만 결과물만 보면 **어떤 부분을 내가 결정했고, 왜 그렇게 결정했는지, 어떤 부분에서 AI의 도움을 받았는지** 명확하게 설명하기 어려울 수 있습니다. 이번 세션에서는 자신의 작업 과정을 돌아보며 **어떤 선택을 했고, 그 선택을 내린 이유는 무엇인지** 설명하고, 이러한 판단이 실제 결과물에 어떻게 반영되었는지 동료와 함께 확인합니다.

또한 **다른 사람은 AI에게 어떤 질문을 했고, 어떤 답변을 바탕으로 어떤 결정을 내렸는지** 살펴봅니다. 같은 제안을 받더라도 서로 다른 판단을 내릴 수 있고, 그 이유를 이해하는 과정에서 내가 미처 생각하지 못한 관점이나 접근 방식을 발견할 수도 있습니다. 서로의 고민과 해결 과정을 공유하며, 혼자 작업할 때는 발견하지 못했던 새로운 방법과 가능성을 찾아봅니다.

미션 1에서 고친 것도 이런 개발 습관과 연결됩니다. 고친 것 하나를 선택해, 무엇을 바꿨고 왜 바꿨는지 드러나는 커밋 메시지로 다시 작성합니다. 고친 것이 없다면 기획서를 고친 일이나 두 파일 가운데 하나를 선택한 일로 대신합니다.

## 3장. 지시와 구성 대조

### 진행 방법

1. 살펴보기 - 각자 선택해 온 대화 기록을 공유하고, 내가 요청한 것을 AI가 생성한 기획서, HTML과 나란히 비교합니다.
2. 이야기 나누기 - 기획서의 어느 줄이 내가 요청한 것이고, 어느 줄이 AI가 스스로 채운 것인지 이야기합니다.
3. 수정 과정 살펴보기 - 기획서와 다르게 동작한 곳을 AI에게 어떻게 말해서 고쳤는지, 한 번에 몇 가지 수정을 요청했는지 확인합니다.
4. 커밋 메시지 서로 읽기 - 2-1에서 작성한 커밋 메시지를 동료와 바꿔 읽고, 어떤 표현이 작업 내용을 더 명확하게 전달하는지 비교합니다.

## 4장. 구성 분석

### 진행 방법

1. **살펴보기** - `기획서.md`를 열어 다섯 항목(누가 쓰나 · 무엇을 하려고 · 화면과 동작 · 필요한 자료 · 완성 기준)을 확인하고, HTML을 열어 각 항목이 어느 화면과 동작이 되었는지 찾습니다.
2. **이야기 나누기** - 기획서의 어느 항목이 HTML에 그대로 옮겨졌고, 어느 항목이 HTML에 드러나지 않는지 이야기합니다.

진행이 어렵다면 다음 순서를 따라갑니다.

1. 기획서의 '화면과 동작'에서 한 줄을 선택합니다.
2. HTML을 열어 그 줄이 어느 버튼이나 칸이 되었는지 찾습니다.
3. 찾기 어려우면 AI에게 "기획서의 이 줄은 HTML의 어느 부분이 맡고 있는지 이름만 알려 줘"라고 질문합니다. 코드를 읽을 필요는 없습니다.

### 4-1. 기획서와 화면

|---|---|---|
| 예시 '새 제목을 추가한다' | 맨 아래 입력칸과 추가 버튼. 새 카드는 미분류에 배치됨 | 추가한 영화를 어디에 둘지 요청하지 않아서 AI가 미분류에 배치한 것 같다 |
| 'TMDB 인증값이 없으면 설정 창을 보여준다' | 상단의 `TMDB 설정` 버튼, 처음 실행할 때 열리는 인증값 설정 팝업 | 검색을 시작한 뒤 오류를 알리는 것보다 검색 전에 값을 입력하게 하는 편이 이해하기 쉽기 때문이다. |
| 'md 파일을 불러오면 영화 기록을 덮어쓴다' | 상단 `불러오기` 버튼, 파일 선택창, 덮어쓰기 확인창 | 잘못된 파일이나 실수로 현재 기록을 잃지 않도록 선택과 확인 단계를 나눈 것 같다. |
| '드래그 앤 드롭으로 티어를 옮긴다' | S~F와 미분류의 각 포스터 칸, 영화 상세창의 티어 버튼 | 마우스 이동을 기본으로 하되 드래그가 불편할 때 상세창 버튼을 보조 수단으로 둔 것이다. |

### 4-2. 기획서와 설계 의도

아래 질문 중 해당하는 것을 선택해 동료와 이야기합니다. 정확한 이유를 몰라도 자신의 생각을 바탕으로 이야기해 봅니다.

- 기획서 다섯 항목 가운데 HTML을 만들 때 가장 많이 사용된 항목은 무엇일까요? 한 항목을 제외하면 HTML이 어떻게 달라질까요?
- 완성 기준 가운데 동료가 읽고 그대로 해 볼 수 있는 문장은 어느 것인가요? 해 볼 수 없는 문장은 무엇이 빠져 있나요?
- 다시 열어도 배치가 남게 만들었다면, 배치는 어디에 적혀 있을까요? AI에게 저장 위치를 질문하면 '브라우저 저장소'(브라우저가 이 컴퓨터 안에 따로 적어 두는 공간)라는 답이 나올 수 있습니다. 이어서 다른 브라우저나 다른 컴퓨터에서 열면 어떻게 될지 이야기합니다.
- `기획서_예시.md`와 내 기획서에서 가장 다른 항목은 무엇인가요? 동료의 기획서도 같은 항목에서 달라졌나요?
- AI가 제안한 큰 기능(회원가입, 온라인 공유)을 포함했다면 HTML 한 장으로 만들 수 있었을까요?
- 두 AI가 같은 기획서로 다른 화면을 생성했다면, 기획서의 어느 줄이 해석의 여지를 남겼을까요?

| | 조사 내용 |
|:-:|---|
| 1 | HTML에 가장 많이 반영된 기획서 항목은 '화면과 동작'이었다. 검색, 티어 줄, 미분류 칸, 상세 팝업, 저장 버튼이 거의 그대로 화면 요소가 됐다. 이 항목이 없었다면 두 AI가 만든 화면의 구조가 더 크게 달라졌을 것 같다. |
| 2 | '다른 브라우저에서 md를 불러오면 영화 기록이 똑같이 복원되고 닉네임과 TMDB 인증값은 유지된다'는 문장은 직접 실행해서 성공 여부를 판단할 수 있어 완성 기준으로 사용하기 좋았다. |

### 4-3. 안전 점검

화면이 그럴듯하게 나오는 것과 기획서대로 동작하는 것은 다릅니다.

| 점검 항목 | 점검 결과 |
|---|---|
| 기획서에 없는데 HTML에 포함된 기능이 있나. 있다면 그대로 둘지 제외할지 | 인증값 보기·숨기기와 연결 확인이 추가됐다. 인증값 오입력을 줄이는 데 도움이 되어 유지하기로 했다. |
| 대화창 미리보기에서만 보지 않고 파일로 저장해 브라우저에서 열어 봤나. 미리보기와 달랐던 점 | HTML 파일로 저장한 뒤 구조와 JavaScript 문법을 확인하고 로컬 서버에서 정상 응답하는 것을 확인했다. |
| (다시 열어도 남게 만들었다면) 그 기록이 이 브라우저에만 남는다는 것을 확인했나. 다른 브라우저로 열면 무엇이 보이나 | 기록은 현재 브라우저의 로컬 저장소에 남는다. 다른 브라우저에서는 빈 상태로 시작하므로 MD 파일을 불러와야 한다. |
| AI가 설명한 동작과 직접 해 본 결과가 다른 곳이 있었나 | 불러오기 범위가 처음에는 닉네임까지 포함돼 있어 의도와 달랐고, 영화 기록만 복원하도록 수정했다. |
| 고치기 전 파일이 남아 있나. 없다면 무엇이 곤란해지나 | AI A 파일은 비교용으로 남아 있지만, B 파일은 같은 파일에 수정했다. 다음에는 수정 전 파일도 따로 남겨 변경 전후를 쉽게 비교해야 한다. |
| 대화 공유 링크를 만들기 전에 대화에 이름 · 연락처 같은 개인정보가 없는지 확인했나 | 이름, 연락처, 실제 TMDB 인증값이 대화에 포함되지 않았는지 확인했다. 인증값은 공유 파일에도 들어가지 않는다. |
| 동료와 가장 달랐던 확인 항목과 그 차이 (5-1에 적었으면 그 행을 가리킵니다) | 코랩 세션에서 동료 결과물을 확인한 뒤 5-1과 함께 작성할 예정이다. |

### 4-4. 완성 기준 재작성

내 기획서의 완성 기준 가운데 직접 해 보고 맞는지 판단하기 어려운 문장을 선택해 다시 씁니다. 동료가 읽고 그대로 해 볼 수 있으면 잘 쓴 문장입니다.

| 기존 문장 | 수정 문장 | 수정 이유 |
|---|---|---|
| 예시 '편하게 쓴다' | '영화를 S칸으로 옮기고 다시 열어도 S칸에 남는다' | 해 보면 맞는지 바로 알 수 있어야 해서 |
| '키가 없거나 잘못되었으면 검색 영역에 안내가 뜬다' | 'TMDB 인증값을 삭제한 뒤 영화를 검색하면 설정 안내와 인증값 설정 버튼이 표시되고 직접 추가는 계속 사용할 수 있다' | 어떤 준비와 행동을 해야 하며 무엇이 보이면 성공인지 분명하게 하기 위해서 |

## 5장. 동료 작업 비교

### 진행 방법

1. **살펴보기** - 동료의 기획서를 읽고, 동료의 HTML을 열어 기획서에 쓴 완성 기준을 그대로 따라 합니다.
2. **이야기 나누기** - 같은 아이디어에서 출발했는데 기획서와 화면이 어떻게 달라졌고, 그 차이가 기능을 더할 때 어떤 영향을 줄지 이야기합니다.

결과물이 달라도 만드는 과정에서 비슷한 문제를 겪었을 수 있습니다. 이야기를 시작하기 어렵다면 다음 항목을 비교해 봅니다.

- **AI의 질문에 어떻게 답했나요?**
  - 등급 종류, 영화를 옮기는 방법, 다시 열어도 남길지를 각자 어떻게 정했는지 비교합니다.
- **두 AI 가운데 어느 AI를 선택했고, 무엇을 보고 결정했나요?**
  - 같은 행동을 두 파일에 해 본 결과로 선택했는지, 화면 모양을 보고 결정했는지 비교합니다.
- **AI가 제안한 큰 기능을 어떻게 다뤘나요?**
- **동료의 완성 기준을 내가 그대로 해 볼 수 있었나요?**

### 5-1. 구현 차이

| | 비교 항목 | 내 방법 | 동료 방법 | 후속 작업 영향 |
|:-:|---|---|---|---|
| 예시 | 다시 열어도 남길지 | 기획서에 '다시 열어도 남는다'를 완성 기준으로 추가함 | 남기지 않기로 함. 다시 열면 처음 상태로 돌아감 | 내 방법으로는 고칠 때마다 다시 열어 저장이 깨지지 않았는지 확인해야 한다 |
| 예시 | 두 AI 가운데 선택한 근거 | 같은 행동 셋을 두 파일에 해 보고 다시 열기가 되는 파일을 선택함 | 화면 색이 마음에 드는 파일을 선택함 | 기능을 더할 때 내 방법으로는 어느 기준이 깨졌는지 바로 확인할 수 있다 |
| 예시 | 작업한 순서 | 기획서를 끝까지 쓰고 HTML을 만듦 | 기획서 일부만 쓰고 HTML을 먼저 받아 본 뒤 기획서를 고침 | 동료의 방법으로는 기획서와 HTML이 어긋난 곳이 남아 있을 수 있다 |
| 1 | TMDB 인증값이 없을 때의 처리 | 페이지 안 설정창에서 입력하고 연결을 확인하며, 인증값은 영화 기록과 따로 저장함 | 코랩 세션에서 확인 예정 | 인증값을 코드에 직접 넣는 방법이라면 파일 공유 전에 매번 값을 지워야 한다. |
| 2 | 저장 파일 불러오기 범위 | 영화 기록만 복원하고 현재 닉네임과 TMDB 설정은 유지함 | 코랩 세션에서 확인 예정 | 복원 범위를 미리 정하지 않으면 다른 환경의 사용자 설정까지 예상하지 못하게 바뀔 수 있다. |

### 5-2. 시사점

| 동료 | 인상적인 점 | 적용 방안 |
|---|---|---|
| 예시 지우 | AI가 회원가입을 제안했을 때 '이 페이지는 나 혼자 쓴다'고 답해서 기획서가 짧고 분명해짐 | 다음 기획서에서는 '누가 쓰나'를 먼저 정해 큰 기능을 걸러 보겠다 |
| 세션 동료 | 코랩 세션에서 동료의 질문 방식과 결과물을 확인한 뒤 작성할 예정이다. | 확인한 내용 중 내 다음 기획서에 적용할 수 있는 방법을 정리할 예정이다. |

## 6장. 개선 계획

### 6-1. 회고

| 항목 | 내용 |
|---|---|
| 조사 중 예상 외 발견 | 같은 기능이라도 인증값을 코드에 넣는 방식과 화면에서 입력하는 방식처럼 예외 처리에 따라 첫 사용 경험이 크게 달라졌다. |
| 반복 작업의 불편 사항 | 기능을 고칠 때마다 추가, 이동, 저장, 불러오기를 다시 확인해야 했고 수정 전 B 파일을 별도로 남기지 않아 비교하기가 어려웠다. |
| 다음 기획서 작성 시 개선점 | 인증정보처럼 내보내면 안 되는 값과 복원할 데이터의 범위를 처음부터 따로 적고, 오류 상황의 화면 문구까지 완성 기준에 포함하겠다. |

### 6-2. 수정 계획

| | 수정 사항 |
|:-:|---|
| 1 | 실제 TMDB 인증값을 입력한 상태에서 한글 검색, 포스터 표시, 잘못된 키 오류 안내를 한 번 더 확인한다. |
| 2 | 다음 작업부터는 초안은 그대로 두고 수정본을 다른 파일명으로 저장해 변경 전후를 비교할 수 있게 한다. |

### 6-3. 유지 결정

고치지 않기로 한 것을 적는 칸은 고칠 것만큼 중요합니다. 그대로 두기로 한 이유가 내가 내린 판단의 기록으로 남습니다.

| 유지 항목 | 유지 사유 |
| ----------- | --------- |
| 단일 HTML과 브라우저 로컬 저장 방식 | 개인 PC에서 혼자 쓰는 기록 도구라는 목적에 맞고 별도 서버나 회원가입이 필요하지 않기 때문이다. |
| S/A/B/C/D/F 고정 티어와 미분류 칸 | 기준이 단순하고 새로 추가한 영화를 먼저 모아 둔 뒤 천천히 분류할 수 있기 때문이다. |

### 6-4. 미해결 사항

미해결 사항을 기록해 두면 다음번에 그 부분부터 살펴볼 수 있습니다.

| 미해결 항목 | 막힌 지점 |
| -------------- | ------- |
| 실제 TMDB 검색의 장기 동작 확인 | 제출 파일에 인증값을 넣을 수 없어 사용자가 발급한 값과 인터넷 연결이 있어야 최종 확인할 수 있다. |
| 동료 작업과의 차이 | 코랩 세션 전이라 동료의 기획서와 HTML을 아직 확인하지 못했다. |

## 7장. 동료평가

세션에서 동료의 파일과 기록을 직접 엽니다. 2-2 진행 체크리스트의 항목 가운데 동료가 한 것에 체크합니다. '…있었다면' · '…고쳤다면'처럼 조건이 붙은 항목은 동료에게 그런 일이 없었으면 체크합니다. 모든 항목에 체크되면 PASS입니다. 내가 받은 평가에서 체크되지 않은 항목이 있다면 그 항목을 고쳐 다시 평가받습니다. 고칠 내용은 6-2 수정 계획에도 적습니다.

- [ ] AI가 먼저 질문하게 하고 답하기
- [ ] 다섯 항목 기획서를 `기획서.md`로 저장하기
- [ ] `기획서_예시.md`와 비교하기
- [ ] 기획서로 HTML을 만들어 `영화_A_초안.html`로 저장하고 브라우저에서 열어 보기
- [ ] 완성 기준을 하나씩 직접 해 보기
- [ ] 회사가 다른 AI에 같은 기획서를 줘서 `영화_B_초안.html` 만들기
- [ ] 두 파일에 같은 행동을 해 보고 하나 선택하기
- [ ] 기획서와 다른 부분이 있었다면 본 대로 말해서 고치기
- [ ] 고쳤다면 수정본을 초안과 다른 이름으로 저장하고 문제가 해결됐는지 직접 확인하기
